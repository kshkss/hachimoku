# ADR-103: 「愚かな土管（Dumb Pipe）」としての同期サーバーとセルフホスト

## ステータス
Accepted

## コンテキスト（背景）
家計簿データを複数デバイス（PC、スマートフォンなど）で同期したいという要求は一般的です。
しかし、ローカルファーストかつE2EE（エンドツーエンド暗号化）の原則を採用したシステムにおいて、サーバー側に複雑な家計簿の集計ロジックや仕訳の集計、ビジネスルールの検証を持たせることは、以下の理由で不合理です：
1. **中身が見えない**: サーバーに届くデータはすべて暗号化されたBlob（バイナリ）であるため、サーバーはデータの妥当性を評価できません。
2. **サーバー維持費**: ビジネスロジックを回す高性能なサーバーやデータベース（RDB、キャッシュなど）を用意すると、ユーザーが増えるほど運営インフラ費用が指数関数的に増加します。
3. **セルフホストのハードル**: 個人データの保存先を信頼できない場合、技術力のあるユーザーは「自分のサーバー（Raspberry Pi、VPS、NAS等）で動かしたい」と考えますが、サーバー構成が複雑だとセルフホストが困難になります。

## 意思決定
同期・共有を担うバックエンドサーバー（`/sync`）は、**「中身を一切解釈しない、ビジネスロジックを持たない、ただ暗号化データを中継するだけの愚かな土管（Dumb Pipe）」**として設計します。

### 1. サーバーのシンプルな責務
* サーバー側は、ユーザー認証、デバイス管理、および「いつ（どのリビジョンで）どのバケットのデータが更新されたか」のインデックス管理だけを行います。
* 取引明細や口座定義の中身は `encrypted_payload` という共通のバイナリフィールド（Blob）として保存するだけで、中身は一切見ません（ブラインド・リレーショナル）。

### 2. シングルバイナリ＆ゼロ運用コスト設計
* バックエンドは **Go** で記述され、依存関係を持たない**単一の実行バイナリ（シングルバイナリ）**としてコンパイルされます。
* データベースには組み込みの **SQLite**（クラウド展開時は Turso や Cloudflare D1 などの軽量エッジDB）を採用。
* 余計な依存ミドルウェア（Redis、外部データベース、キューサーバーなど）を要求しないため、月数百円の最安価なサーバー（または無料枠のサーバーレス環境）で十分に動作し、セルフホストしたいユーザーはコマンドを1行叩くだけでプライベート同期サーバーを構築できます。

## 影響・トレードオフ
* **メリット**:
  * サーバーサイドの開発・保守が極めて簡単（APIエンドポイントが極端に少なく、変更が発生しにくい）。
  * 圧倒的に低コストなサーバー運営。セルフホストコミュニティとの高い親和性。
* **デメリット**:
  * サーバー側での統計分析、AIによる家計アドバイス、メールでの週間サマリー配信など、**「暗号化されていない生データを必要とする付加価値サービス」をサーバー側で実行できません**。これらはすべてクライアントアプリ内のバックグラウンド処理として実装する必要があります。
