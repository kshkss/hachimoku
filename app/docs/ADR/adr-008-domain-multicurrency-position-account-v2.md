# ADR-008-v2: 多通貨・マルチアセットを処理する「1口座1通貨」およびポジション勘定設計

## ステータス
**決定** (ADR-008-v1 より更新。クライアントアプリ /app のドメイン層における簿記計算ロジックにフォーカス)

## コンテキスト（背景）
個人財務管理（家計簿）においては、日本円（JPY）だけでなく、米ドル（USD）などの外貨預金、さらには株式、投資信託、ビットコインといった「価格が常に変動するマルチアセット（コモディティ）」を正確に処理する必要があります。

これらを複式簿記の仕組みで扱う際、以下の2つのアプローチが考えられますが、どちらも深刻な不整合やバグを引き起こします：
1. **「1つの口座に異なる通貨を混在させる」**: 
   * USD建ての口座残高とJPYでの取引を同じバケツに突っ込むと、現在の残高が「為替評価額を反映したもの」なのか「過去の購入履歴の合計」なのかが不透明になり、貸借平均の原則（バランスシートの左右が常に一致すること）が破綻します。
2. **「取引時の日本円換算レートで、すべて日本円としてDBに記録する」**:
   * 購入時点のJPYだけで記録すると、外貨や株式の「数量（口数・株数）」と「現在価値（時価）」の履歴が完全に失われ、将来の為替変動による「含み損益（評価損益）」や、売却時の「実現為替差損益」を自動計算することが数学的に不可能になります。

## 意思決定
`/app` のドメイン層において、複数通貨および投資アセットの整合性を数学的・簿記的に100%保証するため、**「1口座1通貨制」**および**「Position Account（ポジション勘定 / 異種通貨決済勘定）方式」**を強制します。

```
     【 口座 A (USD) 】                   【 口座 B (JPY) 】
      残高: 100 USD                      残高: 15,000 JPY
           │                                   │
           │ (100 USD ── 15,000 JPY で交換)     │
           ▼                                   ▼
  [ 借方: JPY/USD ポジション ]         [ 貸方: USD/JPY ポジション ]
  数量: 100 USD, 価値: 15,000 JPY     数量: 100 USD, 価値: 15,000 JPY
  
  ※ポジション勘定（純資産 / Equity）を必ず介在させ、為替変動（評価・実現損益）を隔離する。
```

### 1. 1口座1通貨（One Account, One Currency）の厳格な強制
* データベース上の口座テーブル（`Accounts`）は、**必ず1つの特定の通貨（またはアセット銘柄コード）に紐づき、かつそれ以外の通貨のデータを保持することを禁止**します（例：SBI証券口座という大枠の中に、「SBI証券(JPY口座)」と「SBI証券(USD口座)」という2つの独立した口座オブジェクトを定義する）。
* これにより、ある口座の残高は、単一の通貨/アセットの単純な算術合計（例：`100 USD` や `5.5 株`）として常に明快に算出されます。

### 2. Position Account（ポジション勘定）方式による取引記録
ある通貨と別の通貨（あるいは株式等）を交換する取引（例：150円のレートで100ドルを購入）を記録する場合、両者の間に必ず **「Position Account」** という特殊な純資産（Equity）勘定を介在させます。

* **仕訳の分解**:
  * 取引1 (JPY口座から減少): `貸方: JPY口座 15,000円` / `借方: JPY/USD ポジション勘定 15,000円`
  * 取引2 (USD口座へ増加): `借方: USD口座 100ドル` / `貸方: USD/JPY ポジション勘定 100ドル`
* このポジション勘定は、**「交換した外貨の元本コスト（取得価額：15,000円）」** と **「取得した外貨の数量（100ドル）」** を対として記憶する役割を果たします。

### 3. 評価損益（含み益）と実現損益の算出ロジック
* **評価損益の算出**: 現在の市場レート（時価）が `1ドル = 160円` になった場合、アプリは「USD口座の100ドル ＝ 16,000円」と「ポジション勘定に記録された取得コスト ＝ 15,000円」を比較し、**「含み益 1,000円」** をダッシュボード（運用中バケツ内）に自動計算してリアルタイム表示します。
* **実現為替損益の決定**: 外貨を売却（または消費）した際は、ポジション勘定から古い取得コストを（FIFOまたは移動平均で）取り崩し、売却額との差額を「為替差損益（収益/費用）」として確定させます。

## 影響
* **メリット**:
  * 複式簿記の貸借対照が、外貨為替レートがどれだけ激しく変動しても「1円の狂いもなく」常に一致し続ける。
  * 株式、投資信託、仮想通貨などのアセットをすべて「通貨のバリエーション」として全く同じポジション方程式で一元管理でき、ドメインモデルが美しく一般化される。
* **デメリット**:
  * 単純な「100ドルを1万5千円で買った」という日常的な1つの入力に対して、裏側で4つの仕訳明細（Journal Entries）を自動生成してデータベースに書き込む必要があるため、仕訳作成（Usecase）のロジックが複雑化する。
