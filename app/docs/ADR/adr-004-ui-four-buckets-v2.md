# ADR-004-v2: 「4つのバケツ」とUI表示マッピング

## ステータス
**決定** (ADR-004-v1 より更新。クライアントアプリ「hachimoku」のUI表示ロジックとマッピング仕様に限定)

## コンテキスト（背景）
裏側のデータベースやドメインロジックにおいて、`hachimoku` は厳格な複式簿記の「5分類（資産・負債・純資産・収益・費用）」に基づいてトランザクションを記録します。これによりデータの整合性は完璧に保証されます。

しかし、一般のユーザーにとって「借方」「貸方」「純資産」といった簿記の専門用語は極めて認知負荷が高く、直感的な家計管理を妨げる大きな障壁となっていました。また、クレジットカードの未払金（負債）や、会社の経費立替（資産）、将来のための車検用積立（資産/負債の保留）が、今「自由に使えるお金」と混ざり合って表示されると、現実の購買力を見誤る原因となります。

## 意思決定
ユーザー向けのフロントエンド表示（UI層）において、簿記の5分類を直接提示することを禁止し、以下の**「4つのバケツ」と「純資金（Net Funds）」**という概念へ直感的にマッピングして表示します。

```
     [ 複式簿記5分類 (ドメイン層) ]                [ 4つのバケツ (UI・表示層) ]
     ┌───────────────────────┐                  ┌────────────────────────┐
     │ 資産 (Assets) ────────┼─────────────────>│  1. 資金 (Liquid)      │ 今すぐ使えるお金
     │                       │                  │  2. 運用中 (Invest)    │ 育てるお金
     │                       └─────────────────>│  4. 保留中 (Pending)   │ 宙に浮いているお金
     ├───────────────────────┤                  ├────────────────────────┤
     │ 負債 (Liabilities) ───┼─────────────────>│  3. 支払予定 (Payable)  │ 出ていく予定のお金
     └───────────────────────┘                  └────────────────────────┘

     【 UI上の最重要指標 】
     純資金 (Net Funds)  ＝  [資金 (Liquid)]  －  [支払予定 (Payable)]
```

### 1. 4つのバケツ（バケット）の定義
1. **資金 (Liquid Funds)**: 現金、普通預金、電子マネーなど、いつでも即座に引き出して決済に使える高流動性資産。
2. **運用中 (Investments)**: 株式、投資信託、暗号資産など、将来の資産形成を目的として運用されており、日常の支払いには使わない資産。
3. **支払予定 (Payables / 旧・負債)**: クレジットカードの未決済分、翌月引き落としの固定費など、近いうちに必ず流出することが確定している義務。
4. **保留中 (Pending)**: 
   * **将来の義務のための積立金**: 車検費用や旅行資金など、特定の目的のために隔離され、日常の「資金」からは除外されるべきお金。
   * **未回収の立替金**: 会社の経費を一時的に個人カードで支払った場合など、最終的に同額が補填されるため費用ではないが、一時的に手元から消失している資産。

### 2. 「純資金 (Net Funds)」の最重要化
ダッシュボードの最上部には、「総資産」ではなく **「純資金 ＝ 資金 (Liquid) － 支払予定 (Payable)」** を最大のフォントサイズで強調表示します。ユーザーが「今使える本当の予算」を一目で誤解なく把握できるようにします。

### 3. おもてなしUI配色・表示ルール
各勘定（バケツ）の残高を表示する際、数値の極性（プラス・マイナス）とビジュアルカラーの不一致による混乱を防ぐための配色ルールを適用します。

* **資産（資金、運用中、保留中の中の資産項目）**:
  * 残高がプラス（黒字・所有）：**緑色**で表示
  * 残高がマイナス（オーバードラフト等）：**赤色**で表示
* **負債（支払予定、保留中の中の負債項目）**:
  * 負債残高は常に**正の数（絶対値）**で表示する（「-50,000円」ではなく「50,000円」と書くことで、直感的に5万円の債務があることを理解させる）。
  * 債務が存在する（通常のプラス状態）：**赤色**で表示（債務がある＝注意状態）
  * 過払い、返金等で負債残高がマイナス（実質的な資産化）：**緑色**で表示

## 影響
* **メリット**:
  * ユーザーは簿記の専門知識がなくても、直感的に購買力を把握でき、家計管理のストレスが皆無になる。
  * 経費の立替や積立金が「今月使いすぎた費用」や「自由に使える資金」に混入する問題が完全に解決する。
* **デメリット**:
  * 仕訳データの入力（ドメイン層）と画面上のバケツ表示（UI層）の間にマッピングレイヤー（View Model）が必要になり、UIプレゼンターでの計算コードが追加される。
