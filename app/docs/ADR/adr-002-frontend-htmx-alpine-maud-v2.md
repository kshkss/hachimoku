# ADR-002-v2: 軽量フロントエンドUIスタック (Maud + HTMX + Alpine.js)

## ステータス
**決定** (ADR-002-v1 より更新。/app内のレンダリング技術およびLSP統合をフォーカス)

## コンテキスト（背景）
家計簿アプリ `hachimoku` のUIは、軽快な操作性とリアルタイムなフィードバックが不可欠ですが、ReactやVueなどのSPA（Single Page Application）フレームワークを全面採用すると、以下の深刻なデメリットが発生します：
1. クライアント側でのステート管理、二重のバリデーション（フロントとバック）、API定義、ビルドツールの肥大化による保守コストの増大。
2. アプリの起動速度（FCP）の低下、およびローカル環境でのメモリフットプリントの増大。

一方で、従来の純粋なサーバーサイドレンダリング（SSR）では、画面全体の白画面リフレッシュが発生し、モダンなアプリとして許容できないユーザー体験になります。

## 意思決定
`/app` のプレゼンテーション層において、SPAフレームワークを採用せず、**「HTML-On-The-Wire（Maud + HTMX）」**と**「最小限のクライアントJavaScript（Alpine.js）」**を組み合わせたハイブリッドスタックを採用します。

```
     [ HTML / CSS (Bulma) ] ── UIスタイル
               │
     [ HTMX (htmx-indicator) ] ── 非同期な部分HTML書き換え (サーバー/WASMへのフェッチ)
               │
     [ Alpine.js (x-data) ] ── モーダル開閉、タブ切り替えなど、ローカルの純粋なUI状態
               │
     [ Maud (Rust Macro) ] ── 型安全かつ超高速なHTMLテンプレート生成 (LSP補完可能)
```

### 1. Maud によるコンパイルタイム型安全マークアップ
サーバーサイド（またはローカルWASMアプリケーション内）でのHTML生成には、マクロベースのテンプレートエンジンである **Maud** を採用します。
* **圧倒的な開発体験（DX）**: MaudはRustマクロとして実装されているため、マークアップコード内での変数埋め込みや制御構文、関数呼び出し時に、元のコード位置情報（Span）が完全に保持されます。これにより、**LSP（rust-analyzer）による自動補完、型エラー検知、定義ジャンプ、リファクタリングが完全に機能**します。
* **実行時エラーの根絶**: テンプレートの構文エラーや型ミスマッチはすべてコンパイル時に検出され、実行時に不完全なHTMLが生成されるリスクを100%排除します。

### 2. HTMX による宣言的な部分画面更新
非同期データ通信やフォーム送信、動的な要素入れ替えには **HTMX** を採用します。
* JavaScriptコードを1行も書くことなく、`hx-post` や `hx-target` などのカスタム属性をHTML要素に付与するだけで、指定した部分DOMの書き換えを実現します。
* ローディング状態は `htmx-indicator` などを利用して宣言的にクラス制御を行い、ユーザーに滑らかなフィードバックを提供します。

### 3. Alpine.js によるクライアントサイドUIコントロール
サーバーとの通信が不要な「純粋なクライアント側でのビジュアル操作」（例：モーダルダイアログの表示/非表示、アコーディオンの開閉、サイドバーのトグル）には、軽量な **Alpine.js** を採用します。
* `x-data` や `x-show` を用いて、マークアップ内に直接インラインで宣言的にローカル状態（State）を埋め込みます。
* Alpine.jsは `defer` 属性を付与して非同期的にロードし、ページのファーストペイントを妨げないように構成します。

## 影響
* **メリット**:
  * JSビルドパイプライン（Vite, Webpackなど）が一切不要になり、クライアントコードが驚異的に軽量化。
  * マークアップのバグがコンパイル時に検知されるため、表示バグが激減。LSP連携によりマークアップの記述効率が激変。
  * 状態（State）の真実のソース（Source of Truth）がバックエンド（またはローカルWASMコントローラ）に一元化され、二重ステート管理の複雑性から解放される。
* **デメリット**:
  * アプリ全体のオフライン動作時、すべての部分HTML生成処理をローカル側のRustコード（またはWASM）内で実行する必要がある（クライアント内でMaudを動かすためのバイナリ統合が必要）。
